# 刷新频率与样本量验收口径（QUOT-407，2026-11-05 老板拍板）

- 日期：2026-11-05（口径拍板）；**2026-11-06 追加 §5 复测结论**（商业 IP 池 15s 档实测）
- 基线：TickHub-CN `main@8ecb8dc`（v1.1.0）；LadderStock PR #111
- 关系：本文件替换 `QUOT-407-endpoint-breaker-semantics.md` §1.1 中「每档 ≥10 分钟 **且** ≥60 次」的样本量条件；熔断/计数口径仍以该文件为准
- 状态：15s 档已有数值结论（§5，**商业 IP 池轮换口径**）；秒级（1s / 5s）仍关闭，放开条件见 §5.4

## 1. 刷新频率

| 项 | 定论 |
| --- | --- |
| 当前档位 | **15s**（默认） |
| 可选档位 | 15s / 30s / 60s，图表下拉选择 |
| 秒级（1s / 5s） | **暂缓**，配置保留、默认隐藏；商业化 IP 代理池上线后启用 |
| 商业池接入 | `provider: pool/commercial/direct` 可插拔，`commercial_url` 填链接即可；实现保留在代码中 |
| 配置形态 | Vite env `VITE_LDST_CHART_REFRESH_SEC`（初始档位）、`VITE_LDST_CHART_REFRESH_SECOND_LEVEL`（放开秒级）；本机选择落 `localStorage['ldst.chart.refreshSec']` |

## 2. 样本量验收

`次数 = 600 秒 ÷ 档位秒数`（向上取整），运行时长一律 ≥600s：

| 档位 | 有效样本下限 | 时长下限 |
| --- | --- | --- |
| 15s | 40 | 600s |
| 30s | 20 | 600s |
| 60s | 10 | 600s |
| 秒级（启用后） | 60 | 600s |

只计真实到达上游的请求；缓存命中、闸门拒绝、熔断拒绝都不计样本（与熔断定论 §1.1 计数口径一致）。被上游拒绝的请求计入**失败**并标注原因。

### 2.1 原「50s 档冲突」的定稿

旧口径「每档 ≥10 分钟 且 ≥60 次」在 50s 档互相矛盾（60 × 50s = 50 分钟）。**定稿：以 ≥10 分钟为唯一时长基准，次数 = ceil(600 ÷ 间隔)**。理由：

1. 慢档只做 RT/行数基线，不承担失败率统计；堆到 60 次只把窗口拉长到 50 分钟，没有额外信息量，还扩大封禁暴露面。
2. 换算次数就是「600s 窗口内的最大尝试数」，与 15s 刷新的产品语义一致，且天然有上界、不会互斥。
3. 50s 档若将来启用，取 12 次 / 10 分钟，不再要求 ≥60 次。

此后再不保留两套样本条件；`scripts/ulist_rate_probe.py` 的 `plan_stage()` 即按此实现。

## 3. 出口封锁的处置

`push2` 族对当前出口 IP 的主机级封锁记为**已知限制**，不阻塞本轮验收：在当前出口按 15s 档继续采集，拒绝请求计失败；结论中必须写明「有效样本不足系出口所致，不是上游速率上限」。不因此调整闸门常量。

## 4. 已知落差（必须随口径一起传达）

界面 15s 刷新不等于上游 15s 新鲜度：TickHub `stock_fund_flow_batch` 缓存 TTL=60s、端点族闸门 25s/60s≤3，15s 刷新多数命中缓存。要真正 15s 粒度需下调 TTL 与闸门常量，属单独审批项。

## 5. 复测结论（2026-11-06，QUOT-465）

替代 §3 里「出口封锁导致 0 有效样本」的缺口：换商业出口后已取到满样本，**15s 档给出数值结论**。

### 5.1 方法

| 项 | 值 |
| --- | --- |
| 端点 | `https://push2.eastmoney.com/api/qt/ulist.np/get` |
| 参数 | `fltt=2`，`secids=1.600519,0.000001,0.300750,1.688981,0.002594`，`fields=f2,f3,f6,f12,f14` |
| 出口 | 商业 IP 池（51 代理 `time=3` 套餐：单 IP 有效期 5 分钟，0.08 积分/IP） |
| 节奏 | 15s/次，串行，无并发 |
| 参数复现 | 仓库脚本 `scripts/ulist_rate_probe.py`（`--stages 15 --min-seconds 600 --mode rate --proxy <商业网关>`）；本次实测用的是一次性脚本 `d51_ulist_rate.py`，未入库、无硬编码凭证需求 |

### 5.2 结果

两批各 20 次，连跑窗口 `19:56:27 → 20:08:18` = **711s ≥ 600s**：

| 批次 | 轮数 | 成功 / 失败 | p50 | max | IP 轮换 |
| --- | --- | --- | --- | --- | --- |
| 第 1 批 | 20 | **20 / 0** | 1.89s | 11.52s | `14.18.73.24` → `180.107.109.209`（第 17 轮，270s 到期更换） |
| 第 2 批 | 20 | **20 / 0** | 2.22s | 4.89s | `14.116.250.185` → `14.116.196.33`（第 17 轮） |
| **合计** | **40** | **40 / 0（100%）** | — | — | 共 4 个出口 IP |

失败分类：429/403 = 0，5xx = 0，连接重置 = 0，超时 = 0，行数不足 = 0（40 次全部返回 `rc:0` 真实行情）。
**样本量达标**：40 ≥ 40，711s ≥ 600s。

### 5.3 关键对照：密集请求必被风控

同一 IP 以 2 秒间隔连发 3 次：`TRY1` 200（4.23s，真实数据），`TRY2`/`TRY3` 均 `RemoteDisconnected`，成功率 1/3。
即风控按**单位时间请求数**触发，不按 IP 时长；15s 间隔（4 次/分钟/IP）落在安全区，秒级连发不安全。

### 5.4 结论与边界（**不要当成已验证**）

1. **15s 档可安全连续运行——限「商业 IP 池轮换」口径。** 本次 711s 内经历 4 个出口 IP（每个约 270s），因此结论是「商业 IP 池 + 15s 档」组合可用。
2. **不能推出「单个 IP 连续 600s 打 40 次」安全**：本轮没有任何单 IP 跑满 600s 的样本。单 IP 安全速率仍无数值结论，需 sticky 出口补测。
3. 链路有长尾：两批分别出现 11.52s / 4.89s 毛刺，生产超时阈值应 ≥25s。
4. **秒级（1s / 5s）继续关闭**：本轮只验证了 15s 档，秒级仍需「≥60 有效样本 + 零 429/403/重置」；若按本口径验收，须先由总经理确认「池轮换口径可替代单 IP 口径」。
5. 采集侧建议落地：`ulist.np` 单路径限速 **≥15s 间隔（≤4 次/分钟/IP）**，禁止同 IP <3s 连发；要更高频只能扩 IP 池并发，不能压缩单 IP 间隔。**闸门常量（`ENDPOINT_MIN_INTERVAL=25s`、60s 窗口 ≤3 次）不下调**——§4 的 60s 缓存 TTL 落差仍然存在。
