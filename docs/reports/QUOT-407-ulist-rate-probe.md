# QUOT-407 ulist.np 秒级安全速率压测报告

- 日期：2026-11-05 22:25–22:30 CST
- 状态：**未取得安全速率数值**。执行环境（直连、无代理池）被上游 `push2` 边缘节点直接断连，探针在第一次请求即按授权规则中止。这是「出口不可用」，不是「东财限速上限」结论。
- 相关：熔断口径见 `docs/decisions/QUOT-407-endpoint-breaker-semantics.md`；探针见 `scripts/ulist_rate_probe.py`

## 1. 授权口径（2026-11-05 老板授权）

| 项 | 值 |
| --- | --- |
| 阶梯 | 0.02 / 0.05 / 0.1 / 0.2 req/s（50s / 20s / 10s / 5s） |
| 每档 | 连续 ≥10 分钟 **且** ≥60 次请求；任一阵出信号即停并回落上一档 |
| 本轮不测 | 1 req/s（秒级）——需单独批准 |
| 时段 | 非交易时段；禁止盘中 |
| 环境 | 非生产实例 + 独立代理池，不改任何闸门常量 |
| 允许失败率 | 总失败 ≤1%、reset ≤1%、`QFSD-7001` ≤0.5%；显式风控（429/403/封禁页）必须为 0；连续失败 ≤2 |

## 2. 方法

采集方式与生产批量调用同形：单进程、单路径、固定 150 只 secid、`fields=f12,f14,f2,f3,f62,f184`、单请求 ≤150 只，逐次记录 HTTP 码、RT、`data.diff` 行数、异常类型与 `errno/winerror`。

- **节奏**：按 `start + k × interval` 对齐，不用「请求完再 sleep」，避免把 RT 累加进实际间隔。
- **reset 判定**：按异常类型 + `errno/winerror`（10053/10054、`ECONNRESET`），不匹配英文消息——中文 Windows 上现有 `_is_connection_reset()` 会漏判（见定论文档 §6）。探针刻意不 import `tickhub_cn`，既不经过生产 25s 闸门，也不会 trip 进程内熔断。
- **中止**：任一 429/403、任一 5xx、任一 reset、连续 2 次失败、连续 2 次行数 <150、非 JSON、p95 连续 3 个窗口 >3× 基线，任一触发即停。
- **判定**：安全档 = 100% 成功 + 零 reset + 行数完整 + p95 ≤2× 基线；上线间隔 = 安全档 ×2（不低于 10s）。5s 安全 → 上线 10s → 秒级可行；≥10s 安全 → 上线 ≥20s → 维持分钟级。

工具：`scripts/ulist_rate_probe.py`（仅标准库，运维机无需装依赖）。输出逐条 JSON + Markdown 结论；`--dry-run` 只打印计划。

## 3. 样本量：授权条件本身有一处冲突

「每档 ≥10 分钟」与「每档 ≥60 次」在 50s 档不能同时成立：60 次 × 50s = **50 分钟**。脚本按两者取大，实际计划为 300 次、约 85 分钟发请求 + 3 次 10 分钟冷却 = **约 120 分钟**。

建议二选一，请老板定：

- **A（推荐）**：每档以 ≥10 分钟为准，50s 档 12 次，总时长约 50 分钟。50s 档只作 RT/行数基线，本来就不是用来测失败率的。
- **B**：坚持每档 ≥60 次，总时长约 120 分钟，需安排一个完整的非交易时段窗口。

## 4. 执行结果：出口被上游拒绝

### 4.1 出口能力检查

首次运行前的连通性预检（授权要求），共向东财发出 **13 次 HTTP 请求**（约 5 分钟，平均 0.043 req/s），另做了 3 次 TCP 连接检查（不含 HTTP）：

| 目标 | 请求数 | 结果 |
| --- | --- | --- |
| `push2.eastmoney.com` / `1.push2` / `7.push2` / `82.push2` / `push2delay` 的 `ulist.np` | 10 | **10/10 连接被断开**（`RemoteDisconnected`，HTTP 与 HTTPS、带/不带 Referer 与 Cookie 均相同） |
| `quote.eastmoney.com` | 2 | 200 |
| `push2his.eastmoney.com`（K 线） | 1 | 200 |
| TCP 443/80 到上述边缘 IP | 3 | 全部可连 |

要点：**不是网络不通**。TCP 能连、`quote` 和 `push2his` 正常返回 200，只有实时行情族 `push2*.eastmoney.com` 在应用层直接断连。因此这是上游针对本出口（云机房 IP）的**主机级策略**，不是参数、Header 或 cookie 问题，也不是速率问题。

### 4.2 探针冒烟

用探针发 1 次请求复现：`reset`、171 ms、`RemoteDisconnected`，按规则立即中止，`安全档：无`。证明探针的判定与中止链路可用。

### 4.3 为什么没有换出口重试

本工作区没有配置代理池（`PROXY_POOL_ENABLE=false`、`PROXY_POOL_LIST` 为空，`logs/proxy_pool.json` 不存在），而授权明确要求「独立代理池」且「只用 `set_proxy_node_enabled` 控节点」。在无获批出口的情况下继续换 IP 试探，等于用未授权出口打上游，已停止。

## 5. 结论

1. **本轮拿不到安全速率数值**，秒级不具备落地依据；**维持分钟级**（`ENDPOINT_MIN_INTERVAL=25s` / 60s 窗口 ≤3 次 / 熔断 600s 不变）。
2. 阻塞点不是上游限速，而是测试出口：需要一个东财 `push2` 不拒绝的出口。
3. 探针、判定规则、中止规则已就绪，出口就位后一条命令即可出数。

## 6. 解除阻塞需要的输入

任选其一：

- 提供一个 `push2` 可达的独立出口（境内住宅/移动代理优先），以 `--proxy` 传入；
- 或批准从生产实例现有出口跑（会与生产共用 IP，风险由老板判定）；
- 或批准在有出口的机器上由运维执行，把 `--json-out` / `--md-out` 产物回帖。

## 7. 在获批出口上的执行命令

```bash
python scripts/ulist_rate_probe.py \
  --codes-file pool_secids.txt \
  --proxy http://<dedicated-egress>:3128 \
  --json-out logs/quot407-probe.json \
  --md-out logs/quot407-probe.md
```

`pool_secids.txt` 为 150 只打榜池快照的 secid（逗号或换行分隔）。盘中运行会被脚本拒绝，需显式 `--force` 才越过（授权不允许）。
